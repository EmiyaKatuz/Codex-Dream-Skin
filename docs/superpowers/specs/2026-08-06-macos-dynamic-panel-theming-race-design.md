# 跨平台动态面板主题刷新与工作区分类稳定性设计

## 背景

Internet Angel 扩展通过 `data-angel-component` 为 Codex 动态组件建立稳定的主题语义。当前 macOS、Windows 和 Linux 使用同一份扩展逻辑：交互后等待 `120ms` 执行一次完整分类，并且只观察少数宿主的直接子节点。

Codex 会分阶段挂载对话导航条、右侧工作区、环境信息和摘要面板。分类可能在内部证据出现前执行，随后又因深层挂载不在现有观察范围内而没有第二次机会。用户最终看到原生灰黑色组件，直到另一轮点击、导航或窗口变化偶然触发分类。

右侧工作区还有一个独立但落在同一语义标记生命周期内的问题。`classifyWorkspaces()` 当前要求候选宽度至少为 `260px`、左边缘位于视口宽度的 `45%` 之后，并贴近视口右边缘。拖动文档面板与对话区之间的分隔条会改变这些几何值；即使面板仍是同一个右侧工作区，重新分类也可能移除 `side-workspace` 标记，使颜色在原生黑色和主题色之间切换。现有测试只使用固定的 `438 x 820` 工作区，未覆盖拖动后的几何变化。

颜色配置没有变化。竞态发生在动态组件的语义标记生命周期。完整诊断见 [`docs/macos-dynamic-panel-theming-race.md`](../../macos-dynamic-panel-theming-race.md)。

## 目标

在三平台共享运行时中消除目标动态组件分类对固定延迟的正确性依赖，同时保持现有分类规则、主题隔离和输入期间的性能约束。

验收标准如下：

- 对话导航条挂载后不等待 JavaScript 分类即可获得主题外观。
- 非组合输入期间，其他目标组件的必需结构证据随元素节点出现后，最迟在下一动画帧完成分类；组合输入期间的相关刷新在 `compositionend` 后下一帧完成。
- 同一帧内的多个相关变更最多触发一次完整分类。
- 普通消息文本和无关流式输出不触发完整分类。
- 右侧工作区拖宽、拖窄或重新分类时保持 `side-workspace` 标记，不依赖 `260px` 或视口 `45%` 阈值维持正确性。
- 共享扩展 JS/CSS 的三平台副本保持一致，并且各平台最终 payload 均包含对应共享内容。

## 范围

本次修改覆盖：

- 对话导航条及标记；
- 对话导航预览；
- 右侧工作区、终端和侧边会话；
- 环境信息与摘要面板；
- 设置、权限和子代理等具有现有稳定结构证据的延迟挂载表面；
- 右侧工作区在分隔条拖动和后续重新分类时的标记稳定性；
- 当前分类器已支持且能够通过结构选择器低成本识别的其他动态表面。

本次不修改：

- `diffs-container` Shadow DOM 内部的源码查看器主题；
- 右侧工作区内部原生黑色子层与顶部横栏的视觉覆盖；
- 快捷键设置页搜索输入框外层搜索带的分类与视觉覆盖；
- 工作区以外的现有组件分类条件和视觉设计；
- 非 Internet Angel 主题；
- Codex 官方应用、签名或 `app.asar`；
- 版本号、安装器和发布流程。

## 方案选择

采用“结构 CSS 兜底 + 过滤式深层观察”。

拒绝以下方案：

- 固定次数延迟复查：仍然依赖猜测挂载时间，并增加无效完整分类。
- 为已知 Portal 或面板逐个安装观察器：宿主自身也可能延迟出现，并会形成需要随 Codex DOM 持续维护的名单。
- 恢复全局 `transitionend`：动画不是组件完成挂载的可靠信号。
- 无过滤的全局深层刷新：流式输出和滚动区域会造成分类频率回退。

## 架构

共享源保持唯一：

- `runtime/internet-angel-extension.js` 负责分类、监听和生命周期。
- `runtime/internet-angel-extension.css` 提供导航条结构兜底。
- 现有同步工具更新 `macos/assets`、`windows/assets` 和 `linux/assets` 中的副本。

不增加依赖或新的运行时模块。现有完整 `classify()` 继续是唯一的语义标记提交点，避免拆分局部分类后与 `currentMarks` 清理机制发生冲突。

### 导航条结构 CSS 兜底

导航条已有稳定的结构片段：`button[class*="navigation-row"]`、标记的 `_marker_` 类片段，以及用于激活态的现有类或 `aria-current`。

现有 `data-angel-component` 选择器与结构选择器合并到同一组规则中，复用已有声明。导航行、标记和激活标记在首次样式计算时即可获得主题外观。JavaScript 仍然写入原有语义标记，供诊断、预览和兼容回退使用。

结构兜底不得扩大到需要几何、文本或多信号校验的面板，避免误伤普通 Codex 表面。

### 右侧工作区结构归属

`workspaceEvidence` 继续作为工作区候选的必要条件。候选位于非左侧导航栏的 `aside` 内时，`aside` 提供稳定的右侧工作区归属，因此不再要求候选同时满足 `260px` 最小宽度、视口 `45%` 左边缘和贴右边缘三个几何阈值。左侧固定栏和浮动栏仍由现有 `selectors.sidebar` 排除，工作区证据继续阻止普通 `aside` 内容被标记。

对不在该 `aside` 结构内的旧版 Codex DOM，保留现有几何条件作为兼容回退。多个候选同时有效时，继续按面积选择最小的有效工作区表面，避免把外层容器和内层实际面板同时标记。

该调整只稳定 `side-workspace` 语义标记，不在本 PR 中增加右侧内部黑色子层的 CSS，也不处理设置搜索带或 `diffs-container` Shadow DOM。

### 过滤式深层观察

现有多个浅层 `MutationObserver` 收敛为一个针对 `document.body` 的观察器：

```js
{ childList: true, subtree: true }
```

观察器回调只处理每条记录的 `addedNodes` 和 `removedNodes`，并立即排除非元素节点。它不观察 `characterData` 或属性变化，也不执行布局测量、文本正则或完整页面查询。

元素根只在自身或后代命中现有分类器的稳定结构证据时才视为相关。证据来自现有选择器，包括导航行、工作区角色、环境折叠按钮、摘要条目、Tooltip、终端、设置入口、权限表面和子代理结构。消息单元可以作为一次性挂载证据；其内部后续文本和普通内容节点不属于刷新证据。

下一帧保证只适用于以元素节点表达的结构证据。仅依赖稍后追加文本才能成立的分类继续由现有交互刷新覆盖，不纳入本次保证；本次不增加文本节点监听，以免流式输出重新触发高频完整分类。

移除记录仅在包含已标记组件或相关结构证据时触发刷新，用于重新选择仍在页面中的候选组件。断开连接节点本身不需要额外清理。

## 数据流

相关挂载的处理顺序如下：

1. Codex 新增或删除深层元素节点。
2. `MutationObserver` 收到 `childList` 记录。
3. 回调过滤非元素节点和无关结构。
4. 命中证据后取消尚未执行的 `120ms` 交互刷新。
5. 回调安排一次 `requestAnimationFrame`。
6. 同一帧内的其他相关记录复用该请求。
7. 动画帧执行现有完整 `classify()`。
8. `currentMarks` 在同一次分类内写入新标记并移除页面中失效的旧标记。

现有 `120ms` 交互刷新继续处理没有产生可识别元素变更的路由兜底，但不再承担异步挂载的正确性。快速路径执行后必须取消对应的待处理延迟任务，避免同一变化被分类两次。

窗口尺寸变化复用同一个动画帧刷新槽。输入法组合期间继续禁止分类并记录待办；`compositionend` 将该待办合并为下一动画帧的一次刷新。

分隔条拖动产生的窗口或布局刷新仍复用现有分类入口。重新分类时，已归属于右侧 `aside` 的工作区不会因为跨过旧几何阈值而失去标记；旧版非 `aside` 结构仍按原有几何回退重新判断。

## 性能边界

观察范围扩大到子树，但完整分类的触发范围缩小到相关结构证据。以下约束必须同时成立：

- observer 回调只遍历本批 mutation 的元素根及其局部后代；
- 不因文本节点、字符变化或普通消息内容执行完整分类；
- 不监听 `transitionend`；
- 不运行周期性短间隔分类；
- 不在 observer 回调内调用 `getBoundingClientRect()`；
- 同一动画帧最多执行一次完整分类；
- 快速刷新与 `120ms` 延迟刷新不得重复执行。

现有 `metrics.classifyRuns` 用于验证无关 mutation 不增加分类次数。无需增加新的性能统计或抽象。

## 生命周期与失败行为

主题安装时执行一次初始分类，然后安装单个深层观察器和现有事件监听器。

`cleanup()` 必须：

- 清除待处理的 `120ms` timeout；
- 取消待处理的 animation frame；
- 断开深层观察器；
- 移除现有事件监听器；
- 重置输入法组合状态；
- 移除所有 `data-angel-component` 标记；
- 删除扩展注册状态。

选择器检查失败或浏览器不支持某个可选 API 时，组件保持原生状态；不得通过宽泛选择器猜测主题对象。现有 `requestAnimationFrame` 不可用时继续使用同步刷新回退。

## 自动化验证

在现有 Internet Angel fixture 中增加以下回归：

1. 初始分类只看到空面板外壳，`120ms` 刷新完成后仍未分类。
2. 在外壳深层加入所需结构证据。
3. observer 回调后、动画帧执行前仍未写入标记。
4. 下一动画帧执行后写入正确的组件标记。
5. 多个相关元素连续挂载只增加一次 `classifyRuns`。
6. 文本节点、普通消息内容和模拟流式输出不增加 `classifyRuns`。
7. 快速刷新取消待处理的 `120ms` 刷新，继续推进计时器不会再次分类。
8. `cleanup()` 断开 observer，并取消 timeout 和 animation frame。
9. 右侧 `aside` 内同一工作区在初始宽度、拖窄到 `260px` 以下、拖宽到左边缘落在视口 `45%` 之前以及再次完整分类后始终保留 `side-workspace`。
10. 不在右侧 `aside` 内的旧结构继续通过原有几何条件分类，缺少工作区证据或属于左侧栏的候选仍不被标记。

CSS 测试必须证明导航行、普通标记和激活标记均具有结构兜底，同时保留原有属性选择器。现有“禁止 `subtree: true`”断言调整为验证深层 observer 使用过滤回调；继续禁止 `transitionend` 和无过滤的 `MutationObserver(scheduleRefresh)`。

## 同步与回归

实现后执行：

```bash
node tools/internet-angel-extension.test.mjs
node tools/sync-runtime-assets.mjs --check
node macos/tests/internet-angel-macos.test.mjs
./macos/tests/run-tests.sh
node windows/scripts/injector.mjs --check-payload
node linux/scripts/injector.mjs --check-payload
git diff --check
```

同步检查必须证明三平台扩展 JS/CSS 副本一致；各平台 payload 检查分别证明对应共享内容已进入最终注入结果。Windows 或 Linux 上无法在当前机器执行的原生 smoke test 交给 CI，并在交接中明确记录证据缺口。

## 实机验收

在真实 Codex 渲染器中完成：

- 连续切换会话 20 次，对话导航条不出现原生灰色等待期；
- 连续打开和关闭右侧文档预览 20 次；
- 拖动文档面板与对话区之间的分隔条，在窄、宽和往返拖动后确认右侧工作区不再变回原生颜色；
- 连续打开和关闭环境信息及摘要面板各 20 次；
- 快速切换会话和右侧标签，语义标记不丢失；
- 滚动长对话并观察流式输出，完整分类次数不因普通文本持续增长；
- 记录分类耗时，与修改前约 `3.7ms` 的实测量级比较，确认没有明显回退。

右侧工作区内部黑色子层、快捷键设置页搜索带和源码查看器 Shadow DOM 黑色内容分别由后续小 PR 处理，不作为本设计通过或失败的依据。

## 完成条件

只有在共享源修改、三平台资产同步、自动化回归通过和可执行的实机验收完成后，才能声明本地修复完成。提交、推送、PR、合并和 Release 必须继续分别陈述；本设计本身不授权发布。
